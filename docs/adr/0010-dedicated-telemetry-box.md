# A dedicated telemetry box runs the observability stack

A second, single-purpose Hetzner server — the **telemetry box**, in Helsinki, a different country than the Falkenstein core-services box — runs the whole observability stack as four version-pinned containers under Docker Compose: Caddy (the only internet-facing piece: automatic TLS, access-token check, forwarding), Grafana (dashboards + alert evaluation), Prometheus (metrics), Loki (logs). The backend and the worker agents instrument once with OpenTelemetry (.NET built-ins: `ILogger`, `Meter`, `Activity`) and push OTLP to the box; senders buffer undelivered batches and retry with original timestamps, so a box outage delays telemetry rather than losing it. Alerts deliver by e-mail plus a dedicated Telegram/Slack channel; healthchecks.io is the external dead-man's switch (every scheduled duty pings it after success, the telemetry box pings liveness — the boxes do not watch each other). Retention: 12 months logs, 13 months metrics, revisited on disk evidence.

The decisive facts: telemetry stays in-house with retention as cheap disk instead of a 14-day free-tier window; the flat ~€4–9/mo box beats a usage-priced SaaS bill projected at ~$70–150/mo at 1–2k jobs/day; the 8 GB app box cannot comfortably carry the stack itself (~1 GB platform budget already committed); and the alarm must outlive the app box — a dead box with Vast auto-top-up ON is exactly when alerting matters most. Reversibility is preserved by the OpenTelemetry seam: swapping the backend (to Grafana Cloud, VictoriaLogs, or anything OTLP-speaking) is an endpoint change, not a code change.

Eyes-open caveats accepted with the choice:

- **Alerting notifies, it does not page** — this softens ADR 0008's binding condition "alerting that pages the operator". E-mail + a chat channel are the delivery paths; a wake-you-up pager (ntfy/Pushover as one more Grafana contact point) is deliberately deferred until it becomes a priority. The upgrade is configuration, not architecture.
- **The telemetry box has no backups.** It is the sole home of log history; a lost disk loses it. Accepted because the durable record of every job (states, attempt records, timings, failure reason codes) lives in Postgres, and the per-attempt raw-log archive in R2 was declined as premature (`docs/v2-features.md`).
- **Worker-log loss window:** a worker agent holds its whole job's logs in memory and retries for its lifetime, but if the box is unreachable for the worker's entire life and the worker is then destroyed, those logs are gone.
- **Loki indexes labels only.** The label set stays tiny (service/env/level); job and attempt ids ride as structured metadata, filtered by scan within Postgres-supplied time windows. Rare needle-in-haystack hunts over months may be slow on a small box; the escape ladder is bigger box → bloom filters → VictoriaLogs as drop-in successor.
- **Direct exposure, no Cloudflare front.** Caddy is the only listener and rejects tokenless requests; automated OS security patching stays on per ADR 0008; Hetzner bills no inbound traffic, so a DDoS is an availability problem, not a cost problem. Cloudflare fronting remains a one-toggle later escalation (the DNS zone is already there). The Grafana login gets strong auth and ideally an IP restriction.
- **No error-tracking product.** Exceptions are structured error logs with alert rules; job failures are already reason-code data on job rows. Sentry (or GlitchTip) is adoptable later as SDK + key without rework.

## Considered Options

- Dedicated Hetzner telemetry box, four pinned containers (chosen) — in-house data, year-scale retention for disk pennies, flat cost, pager survives the app box; costs a second host to patch.
- Grafana Cloud free tier — the runner-up: zero standing ops, alerting survives anything of ours, bundled mobile pager; lost on 14-day log retention, dependence on a third party's free tier staying generous, telemetry leaving our infrastructure, and usage pricing (~$0.50/GB logs + $19/mo platform) at scale.
- On the app box — eliminated: ~1.5–2.5 GB of the 8 GB box, and the alarm dies with the box while Vast auto-top-up keeps billing.
- Hybrid (collection on-box, alerting external) — dominated by both other options; undefended.
- Stack variants: VictoriaMetrics + VictoriaLogs (leaner, faster text search, but less-trodden and second-class in agent tooling — named as Loki's successor if search slows), Grafana's all-in-one `otel-lgtm` image (positioned dev/demo only), Tempo/Mimir/Alloy (traces, clustered metrics, collector agent — nothing at this scale needs them; OTel keeps Tempo addable as configuration).
