# Control-plane hosting survey

Resolves issue #4 (wayfinder research). Survey only — the decision belongs to the "Control-plane hosting choice" ticket (#9).

**Workload**: ASP.NET Core (.NET 9) API container + background worker process(es) + small PostgreSQL. GPU compute is on Vast.ai and large video files in object storage (likely Cloudflare R2), so the control plane is light: API traffic, job orchestration, DB. Launch scale 10–100 users; must scale to 1000s. Requirements: GitHub Actions CI/CD, IaC, monitoring, production practices.

All prices USD unless noted, pay-as-you-go retail, verified against primary sources 2026-08-27. Azure figures are East US meters from the official Azure Retail Prices API (https://prices.azure.com/api/retail/prices); AWS figures are us-east-1. JS-rendered pricing pages that could not be scraped are flagged inline and in [Verification caveats](#verification-caveats).

**One platform note that predates any hosting choice**: .NET 9 is an STS release that reaches end of support 2026-11-10; .NET 10 is the LTS successor (supported to Nov 2028) (https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core). Since everything below runs arbitrary Docker images, the base-image bump is trivial, but plan it before launch.

## 1. Render

1. **.NET 9 containers**: Docker runtime builds and runs any custom Dockerfile, or deploys prebuilt registry images (https://render.com/docs/web-services). .NET is not a native runtime, so Docker is the path. Configurable health-check paths gate traffic cutover. Background workers are a first-class service type (no inbound traffic, same compute plans, no free tier) (https://render.com/docs/background-workers, https://render.com/docs/compute-plans).
2. **Managed Postgres**: Fully managed; flexible plans bill compute + storage ($0.30/GB-month) separately. **PITR is automatic on all paid databases** — 3-day retention on Hobby workspaces, 7-day on Pro+; HA on Pro/Accelerated instance types. Free tier PG expires 30 days after creation and has no backups (https://render.com/docs/postgresql-refresh, https://render.com/docs/free). Small instances ~$7/mo (basic-256mb) to ~$20/mo (basic-1gb) — dollar figures from secondary trackers because render.com/pricing is JS-rendered (https://www.srvrlss.io/provider/render/, https://kuberns.com/blogs/render-postgres-pricing-setup-limits/).
3. **Launch cost**: Starter web $7 (0.5 CPU/512MB) + Starter worker $7 + basic-256mb PG ~$7 + storage → **~$21–25/mo** on the free Hobby workspace; +$25/mo Pro workspace when autoscaling/team features are needed (~$46–50/mo) (https://render.com/docs/compute-plans, https://render.com/docs/new-workspace-plans).
4. **Scaling**: Manual horizontal 1–100 instances on all workspaces; CPU/memory-target **autoscaling requires Pro ($25/mo flat, unlimited seats after the April 2026 plan restructure)**; vertical to 8 CPU/32GB. Regions: Oregon, Ohio, Virginia, Frankfurt, Singapore — fixed at creation (https://render.com/docs/scaling, https://render.com/docs/regions).
5. **Ops burden**: Platform-managed OS, TLS, DB backups/PITR; "All service types redeploy with zero downtime" (disk-backed services excepted) with health-checked instance swap and instant rollbacks (https://render.com/docs/deploys). Bandwidth overage $0.15/GB beyond plan allowance (5GB Hobby / 25GB Pro) (https://render.com/docs/new-workspace-plans).
6. **CI/CD + IaC**: Native GitHub auto-deploy with "wait for CI" gating on Actions; deploy hooks/CLI/REST API for explicit Actions-driven deploys (https://render.com/docs/deploys). **Official Terraform provider** `render-oss/render`, actively maintained though labelled early access (https://github.com/render-oss/terraform-provider-render, https://render.com/changelog/official-render-terraform-provider-now-available-in-early-access); `render.yaml` Blueprints for declarative config.

## 2. Fly.io

1. **.NET 9 containers**: Dockerfile-native (`fly deploy` builds any Dockerfile or takes a prebuilt image). Workers are a `[processes]` group in `fly.toml`, each group on its own independently scaled Machines (https://fly.io/docs/apps/processes/).
2. **Managed Postgres (MPG)**: The recommended offering — legacy "Fly Postgres" is explicitly unmanaged with data-loss caveats (https://fly.io/docs/postgres/). MPG floor is **Basic $38/mo** (shared-2x, 1GB) + $0.28/GB-month storage; HA + pooling on all plans; automatic backups but **no documented retention/PITR window**, and security patching/version upgrades are "under development" (https://fly.io/docs/mpg/). A community post shows an MPG "V2" rearchitecture in beta as of June 2026 — maturity worth probing (https://community.fly.io/t/managed-postgres-v2-beta-now-in-yyz/28057).
3. **Launch cost**: 2 shared-cpu-1x Machines ($2.02/mo at 256MB, $5.92/mo at 1GB each) + MPG Basic $38 → **~$44–50/mo**. Legacy self-managed PG on a Machine would be ~$10–15/mo total but is unsupported (https://fly.io/docs/about/pricing/, https://fly.io/docs/mpg/).
4. **Scaling**: Per-second Machines, vertical to performance classes, horizontal via `fly scale count` per process group; Fly Proxy autostop/autostart for HTTP apps; metrics-based autoscaling requires deploying the separate `fly-autoscaler` component (https://fly.io/docs/launch/autoscale-by-metric/). ~18 regions on a global anycast network (https://fly.io/docs/reference/regions/).
5. **Ops burden**: Closer to managed VMs than classic PaaS. Managed TLS (10 certs free, then $0.10/mo/hostname); rolling deploys by default with canary/blue-green options (https://fly.io/docs/launch/deploy/, https://fly.io/docs/about/pricing/). Egress billed from $0.02/GB (NA/EU); dedicated IPv4 $2/mo; production-grade support costs extra (Standard $29/mo) (https://fly.io/docs/about/pricing/). No free tier for new orgs (secondary: https://www.withorb.com/blog/flyio-pricing).
6. **CI/CD + IaC**: No native Git integration — CD is `superfly/flyctl-actions` + `FLY_API_TOKEN` from GitHub Actions (https://fly.io/docs/launch/continuous-deployment-with-github-actions/). **Official Terraform provider archived March 2024**; Fly recommends flyctl + Actions instead; only community forks exist (https://github.com/fly-apps/terraform-provider-fly, https://fly.io/docs/blueprints/infra-automation-without-terraform/).

## 3. Railway

1. **.NET 9 containers**: Auto-detects and builds a root `Dockerfile` (custom path via `RAILWAY_DOCKERFILE_PATH`); services aren't typed — a worker is just a service without public networking, billed on the same usage meters (https://docs.railway.com/guides/dockerfiles). HTTP health checks gate traffic cutover (https://docs.railway.com/reference/healthchecks).
2. **Postgres**: **Template-based, not a true managed DBMS** — PG runs as a container on a volume you effectively operate (version upgrades are your problem) (https://docs.railway.com/reference/databases). Backups are volume snapshots (daily/weekly/monthly retention tiers), **no PITR** (https://docs.railway.com/reference/backups).
3. **Launch cost**: Hobby $5/mo including $5 usage; meters ≈$10/GB-month memory, ≈$20/vCPU-month CPU, $0.15/GB-month volumes, $0.05/GB egress → a lightly loaded API + worker + PG lands **~$10–30/mo**, the cheapest PaaS at idle-heavy launch scale (https://railway.com/pricing).
4. **Scaling**: Built-in vertical autoscaling (burst to plan limits: Hobby 48 vCPU/48GB per service); horizontal via manually set replicas (Hobby 6, Pro 42), incl. multi-region replicas — but no automatic horizontal scaling policy (https://docs.railway.com/reference/scaling). 4 regions (US-West/US-East/EU-West/SE Asia) (https://docs.railway.com/reference/regions).
5. **Ops burden**: Platform handles OS/TLS and health-gated zero-downtime deploys, **except services with volumes — which includes your Postgres — which take brief downtime on redeploy** (https://docs.railway.com/reference/healthchecks). DB software upkeep is on you; backups are snapshot-grade.
6. **CI/CD + IaC**: Native GitHub auto-deploy with "Wait for CI" gating; CLI deploys from Actions (https://docs.railway.com/guides/github-autodeploys). **No official Terraform provider** — community `terraform-community-providers/railway` only (https://github.com/terraform-community-providers/terraform-provider-railway); config-as-code via `railway.json`/`railway.toml`.

## 4. Heroku

1. **.NET 9 containers**: Docker works on the **Cedar generation only** (Container Registry or `heroku.yml`; must bind `$PORT`, no VOLUME/HEALTHCHECK, x86_64 only); the new Fir generation is Cloud Native Buildpacks only, no Docker (https://devcenter.heroku.com/articles/container-registry-and-runtime, https://devcenter.heroku.com/articles/generations). Alternatively the official .NET buildpack supports .NET 8+ including current .NET 9 SDKs (https://devcenter.heroku.com/articles/dotnet-heroku-support-reference). Worker process types are first-class (separate dynos, billed at dyno price).
2. **Heroku Postgres**: Essential-0 $5/mo (1GB) / Essential-1 $9 / Essential-2 $20 — daily backups but **no PITR/rollback at Essential tier**; Standard-0 $50/mo brings 4-day PITR, 200 connections; Premium adds HA ($200+) (https://www.heroku.com/pricing/, https://devcenter.heroku.com/articles/heroku-postgres-plans). No free tier since 2022.
3. **Launch cost**: Basic web $7 + Basic worker $7 + Essential-0 $5 = **$19/mo**; production-grade (Standard-1X ×2 + Standard-0 PG) = **~$100/mo** (https://www.heroku.com/pricing/).
4. **Scaling**: Manual `heroku ps:scale`; Basic caps at 1 dyno per process type — horizontal scaling starts at Standard ($25/dyno); **native autoscaling only on Performance ($250+/dyno) and Private/Shield tiers**, web dynos only (https://devcenter.heroku.com/articles/scaling, https://devcenter.heroku.com/articles/autoscaling). Common Runtime regions: US and EU only (https://devcenter.heroku.com/articles/regions).
5. **Ops burden**: Lowest of the PaaS group — managed OS/stack, TLS (ACM on paid dynos), preboot rolling releases on Standard+, PG backups/patching handled; note the buildpack path even re-patches your base image on rebuild, which the Docker path sacrifices (https://devcenter.heroku.com/articles/container-registry-and-runtime).
6. **CI/CD + IaC**: Mature native GitHub integration (auto-deploy, wait-for-CI, review apps, pipelines) (https://devcenter.heroku.com/articles/github-integration); **official, actively maintained Terraform provider** `heroku/heroku` (v5.3.x, mid-2026) (https://registry.terraform.io/providers/heroku/heroku, https://devcenter.heroku.com/articles/using-terraform-with-heroku).

## 5. Azure Container Apps (ACA)

1. **.NET 9 containers**: Runs any Linux image. Consumption plan is serverless with scale-to-zero; Dedicated (workload profiles) for steady load (https://learn.microsoft.com/en-us/azure/container-apps/plans). Worker runs first-class as either a no-ingress container app with a KEDA scale rule, or as **Container Apps Jobs** (manual/cron/event triggers, billed only while executing) (https://learn.microsoft.com/en-us/azure/container-apps/jobs). Quirks: a scaled-to-zero app with no ingress and no scale rule "has no way of starting back up" — set `minReplicas: 1` for the worker; multi-replica ASP.NET Core apps must configure Data Protection (https://learn.microsoft.com/en-us/azure/container-apps/scale-app). Cold-start duration is not officially published; keep `minReplicas: 1` on the API if it matters.
2. **Managed Postgres**: Azure Database for PostgreSQL Flexible Server — B1ms (1 vCore/2GiB) $0.017/hr ≈ **$12.41/mo** + 32GiB min storage at $0.115/GB ≈ $3.68 → **≈$16.09/mo**; B2s ≈ $49.64/mo + storage (Retail Prices API; specs at https://azure.microsoft.com/en-us/pricing/details/postgresql/flexible-server/). Backups: automatic, 7-day default retention configurable to 35, PITR to any point (restores to a new server); backup storage free up to 100% of provisioned storage (https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/concepts-backup-restore). **HA is not available on Burstable tier** (General Purpose+ only, doubles compute) (https://learn.microsoft.com/en-us/azure/reliability/reliability-database-postgresql).
3. **Launch cost**: Consumption meters (East US): $0.000024/vCPU-s active, $0.000003/vCPU-s idle, $0.000003/GiB-s; **monthly free grant 180k vCPU-s + 360k GiB-s + 2M requests** (https://azure.microsoft.com/en-us/pricing/details/container-apps/, https://learn.microsoft.com/en-us/azure/container-apps/billing). API (0.5 vCPU/1GiB) + worker (0.25/0.5) both always-on: ~$16/mo fully idle to ~$54/mo fully active; scale-to-zero + jobs can fit largely inside the free grant. **Total with B1ms PG: ≈$16–70/mo, realistically $30–50/mo.** New-account sweetener: 12 months of free B1ms Flexible Server + $200/30-day credit (https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account).
4. **Scaling**: KEDA-based — HTTP concurrency (default 10 concurrent/replica), TCP, or any KEDA scaler; **0 → 1,000 replicas per revision**; huge headroom without re-platforming; Dedicated workload profiles later for cost predictability (https://learn.microsoft.com/en-us/azure/container-apps/scale-app, https://learn.microsoft.com/en-us/azure/container-apps/plans).
5. **Ops burden**: Managed Kubernetes underneath — no node patching; free auto-renewed managed TLS certs for custom domains (https://learn.microsoft.com/en-us/azure/container-apps/custom-domains-managed-certificates); **zero-downtime revisions on every tier** with traffic splitting for blue-green/canary (https://learn.microsoft.com/en-us/azure/container-apps/revisions); DB backups are Flexible Server's job. First 100GB/mo internet egress free, then $0.087/GB (https://azure.microsoft.com/en-us/pricing/details/bandwidth/).
6. **CI/CD + IaC**: Official `azure/container-apps-deploy-action` (prebuilt image, Dockerfile, or source via Oryx++) with `azure/login` (https://github.com/Azure/container-apps-deploy-action). Terraform azurerm covers `azurerm_container_app`, `_job`, `_environment`, domains/certs (https://github.com/hashicorp/terraform-provider-azurerm/tree/main/website/docs/r); Bicep is the docs-native surface. **.NET-specific pull: ACA is the default deployment target for .NET Aspire / azd**, which provisions environment + ACR + Log Analytics + identity automatically (https://aspire.dev/integrations/cloud/azure/configure-container-apps/).

## 6. Azure App Service (Linux containers)

1. **.NET 9 containers**: Web App for Containers runs any single Linux container (port via `WEBSITES_PORT`, one exposed HTTP port, TLS terminated at platform front ends); Docker-Compose multi-container mode is being retired 2027-03-31 in favor of sidecars (https://learn.microsoft.com/en-us/azure/app-service/configure-custom-container). No scale-to-zero. **Worker quirk**: WebJobs are constrained in custom Linux containers (not supported in Alpine images; only `.sh` + the container runtime otherwise) — the clean pattern is a second container app on the same plan at no extra compute cost (https://learn.microsoft.com/en-us/azure/app-service/webjobs-create).
2. **Managed Postgres**: same Flexible Server as ACA (§5.2).
3. **Launch cost**: Linux plans (East US): B1 $0.017/hr ≈ **$12.41/mo** (1 vCPU/1.75GB — hosts both API and worker apps on one plan); P0v3 ≈ $56.58/mo if slots + more RAM wanted from day one (Retail Prices API; specs https://azure.microsoft.com/en-us/pricing/details/app-service/linux/). **Total with B1ms PG: ~$29/mo (B1) or ~$73/mo (P0v3).**
4. **Scaling**: Scale up tiers + scale out instances — Basic max 3 (manual), Standard max 10 (rule-based autoscale), Premium v3 max 30; every instance runs every app on the plan (https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/azure-subscription-service-limits). Coarser than ACA but ample for this workload.
5. **Ops burden**: Self-patching platform; free managed cert (Basic+); **zero-downtime needs deployment slots — Standard/Premium only, no slots on B1**, and auto-swap is unsupported on Linux (manual swap from CI works) (https://learn.microsoft.com/en-us/azure/app-service/configure-ssl-certificate, https://learn.microsoft.com/en-us/azure/app-service/deploy-staging-slots).
6. **CI/CD + IaC**: Official `azure/webapps-deploy` action supports container deploys (https://github.com/Azure/webapps-deploy); mature Terraform azurerm (`azurerm_linux_web_app`, `_slot`) and Bicep/ARM coverage.

## 7. AWS App Runner — disqualified

**App Runner is closed to new customers as of 2026-03-31**: "AWS App Runner is no longer open to new customers"; no new features planned; AWS recommends **Amazon ECS Express Mode** as the replacement (https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html, https://docs.aws.amazon.com/apprunner/latest/api/API_CreateAutoScalingConfiguration.html). Even for grandfathered accounts it was HTTP-only — idle instances get memory but not CPU ("You pay for the CPU usage of only the active subset"), so a queue-polling worker starves and would need Fargate anyway (https://docs.aws.amazon.com/apprunner/latest/dg/manage-autoscaling.html). Not considered further.

## 8. AWS ECS on Fargate (+ RDS)

1. **.NET 9 containers**: Arbitrary Linux containers, x86 or ARM64 (Graviton ~20% cheaper; .NET publishes linux-arm64 natively). API as an ECS service behind an ALB; worker as a second service with `desiredCount: 1` and no load balancer. **ECS Express Mode** (the App Runner successor) provisions service + ALB + autoscaling + networking from one API call at no extra charge (https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-getting-started.html, https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html).
2. **Managed Postgres**: RDS PostgreSQL db.t4g.micro $0.016/hr ≈ **$11.68/mo**, db.t4g.small ≈ $23.36/mo Single-AZ (AWS pricing feed behind https://aws.amazon.com/rds/postgresql/pricing/ — page is JS-rendered); gp3 storage ~$0.115/GB-month (secondary-corroborated, see caveats); automated backups 0–35 days with PITR (https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_WorkingWithAutomatedBackups.BackupRetention.html). Aurora Serverless v2 min running capacity costs ~$43.80/mo — only wins with auto-pause (https://aws.amazon.com/rds/aurora/pricing/).
3. **Launch cost**: Fargate $0.04048/vCPU-hr + $0.004445/GB-hr x86 (ARM cheaper) → two 0.25vCPU/0.5GB tasks ≈ $14–21/mo; **ALB $16.43/mo fixed** + LCUs (~$1–6); public IPv4 $3.65/mo each (~4 needed to avoid NAT); RDS micro + 20GB ≈ $14 → **total ≈$50–65/mo** (https://aws.amazon.com/fargate/pricing/, https://aws.amazon.com/elasticloadbalancing/pricing/, https://aws.amazon.com/vpc/pricing/). **Cost traps**: NAT gateway ($0.045/hr ≈ $32.85/mo + $0.045/GB — avoid via public subnets); new-account Fargate quota of 6 on-demand vCPUs (request an increase early); the classic 12-month AWS free tier is gone for accounts created after 2025-07-15, replaced by a $100–200 credits model (https://aws.amazon.com/vpc/pricing/, https://docs.aws.amazon.com/general/latest/gr/ecs-service.html, https://aws.amazon.com/free/).
4. **Scaling**: Target-tracking service autoscaling (CPU/memory/ALB request count); quotas effectively unbounded (5,000 tasks/service) — the only AWS option with no ceiling and no forced migration (https://docs.aws.amazon.com/general/latest/gr/ecs-service.html).
5. **Ops burden**: Highest setup cost if done raw (VPC, ALB, IAM, task defs); Express Mode collapses it to roles + image. Runtime ops low: no host patching, free ACM certs on the ALB, native rolling deployments (min/max healthy percent), RDS-managed backups.
6. **CI/CD + IaC**: First-class — `aws-actions/configure-aws-credentials` (OIDC), `amazon-ecr-login`, `amazon-ecs-deploy-task-definition@v2`, plus new `amazon-ecs-deploy-express-service` (https://github.com/aws-actions/amazon-ecs-deploy-task-definition); complete Terraform/CDK (`ApplicationLoadBalancedFargateService`)/Pulumi coverage (https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_ecs_patterns-readme.html).

## 9. AWS Lightsail

1. **.NET 9 containers**: Linux images only (fine); pulls from public registries or private ECR. One deployment holds up to 10 containers with one public endpoint — API + worker co-deploy on the same node, internal `<service>.service.local` networking. Public endpoint is HTTPS-only. **Quirk: scaling node count replicates every container, worker included** — the worker must tolerate N copies or move to its own $7–10 service (https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-container-services.html).
2. **Managed Postgres**: $15/mo (1GB RAM/40GB SSD; $30 HA); automatic free backups with **PITR in 5-minute increments, 7 days only** (https://aws.amazon.com/lightsail/pricing/, https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-faq-databases.html).
3. **Launch cost**: Micro $10 or Small $15 node (API + worker) + $15 DB = **$22–30/mo flat** — no ALB/IP/NAT charges; 500GB transfer included; new accounts get 3 months free of the Micro node + $15 DB (https://aws.amazon.com/lightsail/pricing/).
4. **Scaling — the dead end**: max 20 nodes, largest power 4 vCPU/8GB, **no autoscaling** (manual power/scale changes, applied without downtime); DB tops out at $490/32GB with no read replicas. Serves thousands of light users, but growth means re-platforming to ECS — AWS's own positioning. Migration is cheap (same containers + a pg dump into RDS) (https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-container-services.html).
5. **Ops burden**: Very low — bundled LB, HTTPS default domain, free managed certs, versioned health-checked deployments, automatic DB backups. Trade-off: coarse observability (basic metrics + stdout logs).
6. **CI/CD + IaC**: No first-party Action — OIDC creds + AWS CLI (`create-container-service-deployment`, with ECR-private access) (https://docs.aws.amazon.com/cli/latest/reference/lightsail/create-container-service-deployment.html); Terraform `aws_lightsail_container_service` / `_deployment_version` / `_database` exist but coverage is thinner than ECS (https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/lightsail_container_service).

## 10. Hetzner VPS + Coolify (or plain Docker Compose)

1. **.NET 9 containers**: Everything is Docker. Coolify deploys via Nixpacks, your Dockerfile, docker-compose (multi-service), or prebuilt registry images (https://coolify.io/docs/applications/). API + worker fit as two Coolify apps or one compose stack.
2. **Postgres**: Self-hosted container; Coolify provides one-click PG and **scheduled `pg_dump` backups on cron schedules with S3-compatible offsite targets** — no PITR, no documented retention policy, restore drills are on you (https://coolify.io/docs/databases/backups). No managed PG at Hetzner; pairing with external managed PG costs ~$15/mo (DigitalOcean entry: https://docs.digitalocean.com/products/databases/postgresql/details/pricing/) or $25/mo (Supabase Pro, §11).
3. **Launch cost**: After Hetzner's June 2026 price adjustment (https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/): CX23 (2 vCPU/4GB) €5.49/mo; **CX33 (4 vCPU/8GB) €8.49/mo (~$9.99 US)** — comfortable for API + worker + PG; backups add-on 20% of server price (7 rolling dailies) (https://docs.hetzner.com/cloud/servers/backups-snapshots/faq/). Coolify self-hosted is free/open-source; Coolify Cloud $5/mo for 2 servers (https://coolify.io/pricing). **Total ≈€9–13/mo (~$10–15).**
4. **Scaling**: Vertical resize (CX43 €15.99, CX53 €29.49), then multiple servers behind a Hetzner LB (LB11 ≈€7.49/mo — secondary-sourced, see caveats). **No autoscaling primitive**; PG stays single-node unless you build replication; at spiky-1000s-of-users scale you're hand-rolling what a PaaS gives you — though a single CX43/CX53 goes a very long way for a light control plane.
5. **Ops burden — the honest list (high)**: OS patching (unattended-upgrades), Docker/Coolify upgrades, security hardening (SSH keys, firewall, not exposing 5432), monitoring/alerting (add Uptime Kuma/Grafana or SaaS), backup restore drills. TLS is automated (Let's Encrypt via Traefik/Caddy). **Zero-downtime rolling deploys work only with a health check + default container names + no host ports + not-docker-compose** — a compose deploy takes a restart blip (https://coolify.io/docs/knowledge-base/rolling-updates). Realistic steady state: a few hours/month plus incident risk with no vendor to page.
6. **CI/CD + IaC**: Coolify GitHub App integration (push-to-deploy, PR previews) and webhook/API deploys from Actions (Bearer-token API with `deploy` permission) (https://coolify.io/docs/api-reference/authorization). Terraform: **official `hetznercloud/hcloud` provider** (Hetzner-developed, servers/networks/LBs/certs) (https://registry.terraform.io/providers/hetznercloud/hcloud); Coolify itself has only community providers (`coolify-terraform/coolify`) (https://github.com/coolify-terraform/terraform-provider-coolify).

## 11. Supabase — managed Postgres (+ Auth) only

Cannot host .NET; assessed purely as a DB/auth layer under any compute option above.

1. **Plans**: Free $0 (500MB DB, pauses after 1 week inactivity, no backups — **not production-viable**); **Pro $25/mo** ($10 compute credits ≈ Micro instance, 8GB DB included, 250GB egress, 100k auth MAUs); compute add-ons Micro $10 → Small $15 → Medium $60 → 8XL $1,870 (https://supabase.com/pricing). Practical prod floor: $25/mo.
2. **Backups**: Pro = daily backups, 7-day retention; **PITR is a $100/mo add-on per 7-day window** (and needs ≥ Small compute per docs) (https://supabase.com/pricing) — the PITR pricing is the weak spot vs. Flexible Server/RDS where PITR is included.
3. **Connecting from .NET**: Direct 5432 connections are **IPv6 (or a $4/mo IPv4 add-on)**; Supavisor pooler is IPv4-compatible everywhere — session mode 5432 for persistent backends, transaction mode 6543 (no prepared statements — clashes with Npgsql defaults) (https://supabase.com/docs/guides/database/connecting-to-postgres, https://supabase.com/docs/guides/platform/ipv4-address). A Hetzner box has IPv6, so direct connection works there.
4. **Auth**: GoTrue usable from ASP.NET Core — standard pattern is validating Supabase JWTs with JwtBearer middleware; the C# client is community-maintained, not official (https://github.com/supabase-community/supabase-csharp). 100k MAUs on Pro dwarfs the target scale.
5. **IaC**: Official Terraform provider (`supabase/supabase`) for projects/settings — not in-DB schema (https://supabase.com/docs/guides/deployment/terraform).

**Verdict as a component**: at $25/mo it costs more than Flexible Server B1ms ($16) or RDS micro ($14) while including less-flexible PITR; it earns its keep only if Supabase Auth (or its dashboard/API layer) is actually wanted. Otherwise the host platform's own managed PG is simpler (same VPC/network, one bill, one IaC provider).

## Shortlist for the decision ticket

Three options spanning the trade-off spectrum:

### 1. Azure Container Apps + PostgreSQL Flexible Server — managed, first-party .NET, longest runway (~$30–50/mo typical, $16–70 envelope)
The strongest "grow without re-platforming" option: any Linux container, first-class worker story (no-ingress apps + Jobs), KEDA autoscaling 0→1,000 replicas, zero-downtime revisions on every tier, free managed TLS, PITR-included Postgres at $16/mo, mature Terraform/Bicep, official GitHub Actions, and the .NET Aspire/azd gravity. Trade-off: consumption billing is an envelope rather than a flat number, and Azure brings hyperscaler complexity (resource groups, identities, meters) compared to a PaaS. ECS Express Mode + RDS (~$50–65/mo) is the equivalent AWS play if AWS is preferred for other reasons, at ~1.5× the cost due to ALB/IPv4 overhead.

### 2. Render — simplest production-shaped PaaS (~$21–25/mo; ~$46–50/mo with autoscaling)
The balance point: Docker-native, first-class background workers, genuinely managed Postgres with PITR on all paid tiers, zero-downtime deploys by default, native GitHub CI gating, official (early-access) Terraform provider. Trade-off: autoscaling and prod features sit behind the $25/mo Pro workspace, ceilings are lower than a hyperscaler (100 instances, 5 regions), and pricing/features have churned recently (April 2026 restructure). Railway is cheaper (~$10–30) but its snapshot-only, restart-blipping Postgres disqualifies it for a job-orchestration DB; Heroku's equivalent production shape costs ~$100/mo; Fly's managed PG floor ($38) and archived Terraform provider weaken it.

### 3. Hetzner CX33 + Coolify — cheapest-with-ops (~€9–13/mo)
An order of magnitude cheaper than everything else and plenty of headroom on one box; official Hetzner Terraform provider; Coolify gives push-to-deploy, TLS, and scheduled S3 Postgres dumps. Trade-off: you are the SRE — patching, hardening, monitoring, backup restore drills, no PITR, no autoscaling, single-node DB, and rolling deploys only under Coolify's specific conditions. Right choice only if the ~$25–40/mo saved is worth a few hours/month of ops and higher incident risk for a revenue-bearing control plane.

**Also-rans**: Lightsail ($22–30, near-zero ops) is genuinely attractive but its no-autoscaling 20-node ceiling makes it a deliberate two-platform plan; App Service is fine but its worker/slots story is clumsier than ACA at similar cost; App Runner is closed to new customers; Supabase only makes sense as a DB/auth add-on, not a host.
